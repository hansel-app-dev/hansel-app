## Problem

The second toolbar control is disabled. Users need to navigate drawing content larger than the visible Allocation Plan area without holding Space or changing Signs.

## Outcome and success metrics

Hand mode pans overflowing drawing content on either axis with zero Sign writes, while the sidebar, header, toolbar, file selector, zoom controls and drawer remain fixed.

## Non-goals

- Free canvas translation beyond scroll boundaries, inertia, new zoom gestures, new backend functionality or persisted viewport state.
- Enabling rectangle, line or comment tools; changing Move or Add sign semantics outside temporary pan behavior.

## Requirements

- REQ-001: Enable the second toolbar button as Hand for every user with existing view access, including Viewers. Selecting it makes Hand the sole active tool, with the reference blue square and white hand icon. Preserve toolbar geometry and the three remaining disabled tools. Move remains the initial tool and resets on plan/file changes.
- REQ-002: With Hand active, hovering the drawing viewport shows an open-hand grab cursor; primary-pointer dragging shows grabbing. Drag the drawing in the pointer direction by updating viewport scroll offsets from the gesture's starting position. Support horizontal and vertical overflow independently, clamped to valid scroll bounds. If content fits, dragging must not shift it outside its fitted position. Signs remain visually attached to the drawing with unchanged coordinates.
- REQ-003: Hand gestures may start over blank drawing content or an existing Sign, but never select, create, edit or reposition a Sign. Suppress the click following a pan gesture, including temporary Space-pan. Existing selection/drawer may remain open; toolbar, zoom, file selector and drawer controls must not initiate viewport panning.
- REQ-004: Releasing the pointer, pointer cancellation, lost pointer capture, Escape, window blur, file changes or unmount end the current pan and release capture safely. Keep the last bounded scroll position on cancellation. Escape ends the gesture but retains Hand mode. Prevent native image drag, text selection and competing touch scrolling while handling the pan gesture; ignore non-primary pointers and non-left mouse buttons.
- REQ-005: Reuse Space as a temporary pan override in Move/Add sign modes. Releasing Space restores the selected tool; when Hand is selected, releasing Space must not disable Hand. Tool changes retain existing pending-mutation and unresolved-edit guards. Switching tools ends any active pan without a trailing Sign action.
- REQ-006: Give Hand an accessible name, tooltip, aria-pressed state and visible focus. Keyboard users can activate it using standard button keys; when the drawing viewport itself is focused in Hand mode, unmodified arrow keys scroll 40 CSS pixels in the corresponding direction, within bounds, without creating or moving Signs. Do not intercept keys in inputs, drawer controls or other buttons. Preserve zoom shortcuts and native wheel/trackpad scrolling.
- REQ-007: Add Hand-active, overflowing and dragging states to Storybook. Preserve accessible, non-overlapping controls at desktop, intermediate and narrow viewport widths, including with an open drawer. No server writes or new telemetry are generated by panning.

## Acceptance scenarios

### AC-001 — Pan overflow [REQ-001, REQ-002, REQ-007]

- Given a zoomed drawing larger than its viewport, when Hand is activated and dragged, then only the drawing scrolls, the cursor changes grab to grabbing to grab, and fixed UI stays fixed.
- Given content that fits or an axis already at its boundary, when dragged further, then content does not move beyond valid scroll bounds.

### AC-002 — Protect Signs [REQ-003, REQ-005]

- Given existing Signs and either a manager or Viewer, when a Hand gesture starts on a Sign or blank drawing and ends, then no Sign is selected, created, moved or saved by that gesture.
- Given Move or Add sign, when Space-pan ends, then the prior tool resumes without a trailing Sign action.

### AC-003 — End and reset [REQ-004, REQ-005]

- Given an active pan, when released, cancelled, interrupted by Escape/blur/lost capture or unmounted, then dragging stops and capture is released safely.
- Given Hand mode, when a file changes, then Move is active on the new file; when Space alone is released, Hand remains active.

### AC-004 — Keyboard and access [REQ-001, REQ-006, REQ-007]

- Given a Viewer and a keyboard, when Hand is activated and arrow keys are pressed with the drawing viewport focused, then the viewport scrolls within bounds while Signs remain unchanged.
- Given focused drawer inputs or toolbar controls, when typing or activating them, then no unintended viewport pan occurs.

## UX and accessibility

Use the supplied hand and grabbing states and the existing toolbar's active styling. Keep pan affordances available even when the content currently fits, so subsequent zoom does not require reselecting the tool. Announce selection through button pressed state; use ordinary focus navigation rather than adding global letter shortcuts.

## API and integrations

No API changes or new external integrations. Reuse the existing drawing viewport and Sign interfaces without mutations from Hand mode.

## Data and migration

No database changes. Scroll position, pointer capture and selected tool remain local transient UI state. Site, Allocation Plan and Sign ownership remain unchanged.

## Security and privacy

Respect existing Site Access; Hand does not require MANAGE_SIGNS. It must not grant editing capabilities or expose additional data. Do not log pointer positions or document content.

## Reliability and observability

Use bounded scroll offsets and deterministic gesture cleanup. No timers, network requests or retries are necessary for panning. Existing load errors, Sign save protections and monitoring remain unchanged.

## Test strategy

After approval, add failing tests for Hand selection, both overflow axes, fitted content and boundaries, drag from Signs without mutation/selection, trailing-click suppression, pointer capture cleanup, Space override, file reset, keyboard scrolling and Viewer access. Run toolbar/viewer/Sign regression tests, lint, typecheck, app and Storybook builds; browser-check grab/grabbing, actual scrolling and responsive layouts.

## Rollout and rollback

Frontend-only change in the existing Sign-enabled viewer. On approval, supersedes only the Hand-disabled requirement of `allocation-plan-toolbar`, adding a third active mode; the three other deferred tools stay disabled. The legacy viewer retains its existing controls. Revert the frontend change to disable Hand without changing saved data.
